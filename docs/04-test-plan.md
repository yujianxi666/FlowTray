说明：自动化环境里，代理进程的令牌被限制，注册表写入返回 `ERROR_ACCESS_DENIED`（同一命令由 PowerShell 执行则成功），因此「设置 → 应用」中的卸载项未能在本机自动化里验证；安装程序对此有 `reg.exe` / `.reg` 导入的兜底路径，普通用户环境下原生 API 写入正常。

## 2.2 启动失败 / 安装失败的定位（0.2.1）

现象：双击 exe 弹出「FlowTray 启动失败 … Failed to setup app … 拒绝访问 (os error 5)」，安装包弹出「无法创建安装目录 … 拒绝访问 (os error 5)」。

定位过程：

1. 应用日志没有新记录、`%APPDATA%\FlowTray\webview` 未创建 → 失败发生在创建 WebView2 数据目录之前/之内的写操作。
2. 同一份 exe 复制到桌面、`%APPDATA%`、`%USERPROFILE%\Documents` 根目录都能正常运行 → 与程序本身无关，与「从哪个目录运行」有关。
3. `icacls` 显示工作区目录带有 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`；在该目录生成的 exe 继承低完整性标签，Windows 按文件的信任标签以低完整性运行进程，低完整性进程无法写入 `%APPDATA%` / `%LOCALAPPDATA%`（返回 `ERROR_ACCESS_DENIED`）。

修复：`icacls release\*.exe /setintegritylevel Medium`（脚本 `scripts/relabel-release.ps1`）。修复后同一目录直接运行、安装到 `%LOCALAPPDATA%`、写入卸载注册表项均正常。

## 4. 复现方式

```powershell
# 单元测试
pnpm test
cargo test --manifest-path src-tauri/Cargo.toml

# 启动带远程调试的实例
$env:FLOWTRAY_USER_DATA = "C:\temp\flowtray-e2e"
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9222"
.\src-tauri\target\x86_64-pc-windows-gnu\debug\flowtray.exe
```

然后用任意 CDP 客户端（`http://127.0.0.1:9222/json/list`）连接页面，直接调用 `window.flowtray.*` 与 `window.flowtray.__e2e.*` 验证业务命令；截图用 `Page.captureScreenshot`。

## 5. 本轮发现并修复的问题

| # | 问题 | 原因 | 修复 |
| --- | --- | --- | --- |
| 1 | 启动后主线程卡死、窗口不显示 | `edge::spawn` 直接在调用线程运行轮询循环，阻塞事件循环 | 轮询放入独立线程 |
| 2 | 主线程死锁 | 广播线程持有数据库锁时同步刷新托盘菜单 | 托盘刷新改为主线程派发，广播不再跨线程触达 UI |
| 3 | 首次显示空白（透明窗） | WebView2 透明窗首次程序化显示不合成 | 首显后做一次 160ms hide/show 强制挂载 |
| 4 | 窗口没贴到屏幕边缘 | 进程未启用 Per-Monitor DPI，坐标被虚拟化 | 启动时 `SetProcessDpiAwarenessContext(PMv2)`，几何统一用逻辑像素 |
| 5 | 窗口尺寸与 WebView 不一致 | 用 Win32 `SetWindowPos` 传物理像素，tao 不感知 | 改用 Tauri `set_size/set_position(Logical*)` |
| 6 | 图片缩略图不显示 | CSP 的 `img-src` 未允许 `http://flowtray.localhost` | 前后端 CSP 同时放行 |
| 7 | 拖拽目标注册数量为 0（诊断误导） | 在 worker 线程读取 `thread_local` 集合 | 注册结果在主线程统计并记录 |
| 8 | 日志脱敏失效（路径吞掉邮箱） | 路径扫描未在空白处结束 | 扫描遇空白/逗号即止 |
| 9 | Rust 单元测试失败 | 同上 | 同上 |
